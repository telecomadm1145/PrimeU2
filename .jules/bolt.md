## 2024-05-13 - WndProc WM_PAINT Allocation
**Learning:** The emulator's Win32 `WndProc` handles rendering during `WM_PAINT` messages, which occur frequently. Previously, it dynamically allocated and deallocated a large buffer (`new uint32_t[lcd->xRes * lcd->yRes]`) every single frame. This is a severe performance anti-pattern for a rendering loop, leading to heap fragmentation and OS overhead. Using a `static` local vector poses a reentrancy thread-safety risk since `WndProc` is a global message handler that can be called recursively or from different UI threads.
**Action:** When optimizing tight loops like UI renderers in C++, always prefer reusable preallocated buffers over per-frame heap allocations. Use `thread_local std::vector` inside window procedures to ensure thread safety across multiple UI threads while preserving the reused memory between calls.
