## 2024-05-18 - SDL Event Loop & WM_PAINT Frame Rendering Bottleneck
**Learning:** The background SDL event thread in PrimU2 used `SDL_PollEvent` in an infinite `while(1)` loop, resulting in a busy-wait spin that fully pegs a CPU core to 100%. Additionally, the Win32 message loop (`WM_PAINT`) performed a dynamic heap allocation (`new uint32_t[]`) and floating-point division per pixel for every frame (~60 FPS), creating significant GC pressure and CPU overhead.
**Action:** When inspecting an event pump loop (`while(1)`), check if `SDL_WaitEvent` (or a blocking equivalent) is applicable instead of `SDL_PollEvent`. Ensure frame-rendering logic in `WM_PAINT` or similar hot paths use static/reusable buffers (like `static std::vector`) to prevent heap thrashing, and hoist invariant math operations outside of per-pixel nested loops.
